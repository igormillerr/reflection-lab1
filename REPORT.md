# Java Reflection — генератор случайных объектов

Лабораторная работа № 2 по углублённой Java.

Проект реализует генератор случайных значений и объектов по переданному `Class<T>`. Для создания пользовательских объектов используется **Java Reflection API**: генератор анализирует доступные конструкторы, определяет типы их параметров и рекурсивно создаёт необходимые аргументы.

## Возможности

| Категория                       | Поддержка                                                                                             |
|---------------------------------|-------------------------------------------------------------------------------------------------------|
| Примитивы и обёртки             | `byte`, `short`, `int`, `long`, `float`, `double`, `boolean`, `char` и соответствующие классы-обёртки |
| Строки                          | Случайные строки `String`                                                                             |
| Перечисления                    | Случайная константа непустого `enum`                                                                  |
| Массивы                         | Массивы поддерживаемых типов, в том числе примитивов и пользовательских классов                       |
| Списки                          | `List.class` и `List<T>` в параметрах конструкторов                                                   |
| Отображения                     | `Map.class` и `Map<K, V>` в параметрах конструкторов                                                  |
| Пользовательские классы         | Создание экземпляров через публичные конструкторы                                                     |
| Интерфейсы и абстрактные классы | Выбор конкретной реализации по аннотации `@Generatable`                                               |
| Рекурсивные модели              | Ограничение повторений класса в текущей цепочке генерации                                             |

Генератор не содержит специальных условий для классов из исходного шаблона лабораторной: пользовательские типы обрабатываются с помощью Reflection.

## Использование

```java
import org.example.generator.Generator;

import java.util.List;
import java.util.Map;
import java.util.Random;

Generator generator = new Generator();

Integer number = generator.generateValueOfType(Integer.class);
String text = generator.generateValueOfType(String.class);
int[] numbers = generator.generateValueOfType(int[].class);
List<?> items = generator.generateValueOfType(List.class);
Map<?, ?> entries = generator.generateValueOfType(Map.class);

// Пользовательские классы и полиморфные типы:
Triangle triangle = generator.generateValueOfType(Triangle.class);
Shape shape = generator.generateValueOfType(Shape.class);
```

Здесь `Triangle` и `Shape` — классы из шаблона лабораторной; для их использования требуются соответствующие импорты. Вызовы выполняются в контексте, допускающем обработку исключений Reflection.

В конструктор генератора можно передать собственный `Random`, например для воспроизводимости последовательности случайных решений:

```java
Generator generator = new Generator(new Random(42));
```

### Генерация пользовательских объектов

Для пользовательского класса генератор:

1. Получает публичные конструкторы через `getConstructors()`.
2. Случайно выбирает один из них.
3. Получает типы параметров через `getGenericParameterTypes()`.
4. Рекурсивно генерирует аргументы и вызывает конструктор через `newInstance()`.

`ParameterizedType` используется для извлечения типов элементов `List<T>`, а также ключей и значений `Map<K, V>` из параметров конструктора. Например, для конструктора с параметром `Map<Integer, Product>` генерируются ключи типа `Integer` и значения типа `Product`.

## Аннотация `@Generatable`

Аннотация задаёт **список допустимых реализаций интерфейса или абстрактного класса**. Это позволяет запрашивать объект по абстрактному типу без специальных проверок его имени внутри генератора.

Пример использования на интерфейсе `Shape`:

```java
@Generatable(implementations = {
        Rectangle.class,
        Triangle.class
})
public interface Shape {
    // Методы интерфейса
}
```

**Правила интерпретации:**

- Аннотация применяется к запрашиваемому интерфейсу или абстрактному классу.
- Массив `implementations` должен содержать хотя бы один класс.
- Каждый указанный класс должен быть конкретным (не интерфейсом и не абстрактным классом) и быть совместимым с аннотированным типом (`isAssignableFrom`).
- Генератор проверяет весь список, затем случайно выбирает одну реализацию и создаёт её обычным механизмом Reflection.
- Конкретным реализациям не требуется собственная аннотация `@Generatable`.
- Если аннотация отсутствует, список пуст или содержит недопустимую реализацию, генерация завершается `IllegalArgumentException`.

Аналогичный подход работает с собственными абстрактными классами и их наследниками.

## Ограничения и особенности

- **Прямой запрос `List.class`** создаёт `ArrayList<String>`, поскольку `Class` не содержит информации о generic-аргументах.
- **Прямой запрос `Map.class`** создаёт `HashMap<String, Integer>` по той же причине.
- **Параметризованные коллекции** поддерживаются для `List<T>` и `Map<K, V>` в параметрах конструкторов. Произвольные разновидности `Type`, все generic-комбинации и все реализации интерфейсов коллекций не поддерживаются.
- **Размеры массивов и коллекций** выбираются случайно в диапазоне от 1 до 5. Для `Map` итоговый размер может быть меньше числа сгенерированных пар из-за повторяющихся ключей.
- **Строки** состоят из строчных латинских букв; длина — от 1 до 15 символов.
- **Конструкторы:** генератор использует только публичные конструкторы; конструктор выбирается случайно.
- **Рекурсия:** один и тот же пользовательский класс допускается не более трёх раз в текущем пути создания объектов. При достижении ограничения для очередной рекурсивной ссылки возвращается `null` (например, для дочернего узла дерева).
- **Предметные ограничения** не учитываются автоматически: случайные аргументы могут не соответствовать проверкам внутри пользовательского конструктора, например требованию положительных размеров фигур.
- Публичный API принимает `Class<T>`; отдельного публичного API для передачи произвольного `Type` нет.

## Обработка ошибок

Генерация завершается исключением, если объект невозможно создать:

- `IllegalArgumentException` — неподдерживаемый тип, отсутствие публичного конструктора, пустое перечисление или неверная конфигурация `@Generatable`.
- `NullPointerException` с поясняющим сообщением — `null` вместо класса в публичном API или `Random` при создании генератора.
- `IllegalStateException` — пользовательский конструктор выбросил исключение. Исходная ошибка сохраняется как `cause`.

Ошибки доступа или создания экземпляра, возникающие непосредственно в Reflection, могут передаваться вызывающему коду в виде соответствующих проверяемых исключений.

`null` не используется как универсальный признак неудачной генерации. Он применяется только для завершения рекурсивных ссылок при достижении заданного лимита; если конструктор не допускает такое значение, создание объекта может завершиться исключением.

## Сборка и тестирование

**Технологии:** Java 21, Gradle, JUnit.

Запуск тестов в Linux/macOS:

```bash
./gradlew clean test
```

В Windows:

```bat
.\gradlew.bat clean test
```

JUnit-тесты покрывают поддерживаемые категории типов, создание пользовательских объектов, параметризованные коллекции, рекурсивные структуры, полиморфную генерацию через `@Generatable` и ошибки создания объектов.

В репозитории настроен workflow `.github/workflows/java-tests.yml`. **GitHub Actions** запускает тесты при событиях `push` и `pull_request`.
